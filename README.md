## Engine detectado

**NO es Unity, ni Godot, ni nativo.** Es un juego **HTML5 construido con Scirra Construct 3** exportado como app **Apache Cordova (WebView)**:

- `assets/www/scripts/c3runtime.js` (1,88 MB) — runtime oficial de Construct 3 (cabecera: *"Generated by Construct, the game and animation creation tool"*).
- `assets/www/scripts/c3main.js` — entrypoint ES-module que importa el runtime + plugins C3.
- `assets/www/box2d.wasm` + `box2d.wasm.js` (244 KB + 276 KB) — **Box2D compilado a WebAssembly** para la física.
- `assets/www/data.json` — proyecto Construct serializado (event sheets, layouts, object properties) — **aquí vive toda la lógica del juego**.
- El lado Java/Kotlin es un shell mínimo: `MainActivity extends CordovaActivity` (~15 líneas) + plugins Cordova.

Consecuencia práctica: la lógica no está en el DEX sino en JS legible (`main.js`, `data.json`), sin ofuscar en la parte del juego.

## Regenerar lo omitido

El `.gitignore` excluye binarios **repetibles** para no inflar el repo (ahorra ~180 MB). Regenerables con:

```bash
# smali completo (160 MB, redundante con raw/classes*.dex + sources/)
java -jar /opt/tools/apktool_3.0.3.jar d apk/com.iron.ball.apk -o apktool_full

# XAPK original (22 MB, contiene el mismo base APK ya incluido en apk/)
apkeep -a com.iron.ball -d apk-pure xapk_dir
```

Omitido y por qué:
- `apktool_out/smali/` + `smali_classes2/` (160 MB): disassembly del bytecode — ya está como DEX en `raw/` y como Java en `sources/`.
- `apktool_out/assets/` (8,8 MB): copia idéntica de `raw/assets/`.
- `com.iron.ball.xapk` (22 MB): contenedor del mismo APK ya incluido.

Herramientas usadas: apkeep 1.0.0, unzip, apktool 3.0.3, jadx 1.5.7, OpenJDK 17. Fecha del análisis: 2026-11-26.
